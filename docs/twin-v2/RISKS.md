| **KTX2 textures are unproven under WebGPU** (P01a): no encoder is installed, so no real KTX2 file was loaded in the spike. The build switches to KTX2 by itself once `ktx` is on the PATH, and the loader has `KTX2Loader` wired with the transcoder served from `/vendor/twin/basis/`; the first session after the owner installs it must run `node scripts/twin/build-assets.mjs --force` and `check-pipeline.mjs` on WebGPU and with `--force-webgl` |
| **Loading a dashboard page makes the app write speech clips into `public/voice/` and `voice-bank/`** (P01a): 36 new files appeared during the bench | Before each commit: `git status`, and stage only the sub-phase's files | Owner to decide whether those folders belong in git | open, owner to decide |
| **Visitors without WebGPU wait 17 to 22 s for the first frame** (P01a): the WebGL2 fallback compiled shaders for 8.7 s and took 9.6 s over its first frame, against 9 to 11 s in all on WebGPU | P01c: measure the fallback's start with the real asset pipeline, compiling zone by zone | Fewer material variants; a lighter post chain on the fallback; a loading screen that shows progress (P01b, P13a) | open, reduced (P01c): with the test zone (5 materials, 15 pipelines) the forced fallback is usable in 1.1 to 1.9 s and has the zone in 1.7 s later, against 0.9 s on WebGPU; pipelines are compiled one at a time before their draw is added, so the wait is spread out and no frame stalls. The 17 to 22 s of P01a came from 46 pipelines with shadows and post effects, which do not exist yet: measure again in P02c |
| **One black first frame on WebGPU** (P01a): once, in the dev server, the page stayed black with a validation error about a 300 x 150 depth buffer; not seen in 45 production runs | P01b: size the renderer before the first frame; reload the page 20 times in dev and production | Rebuild the renderer on its error event, as for a lost context | retired (P01b): explained and fixed. React Three Fiber configured the canvas twice at start and swapped in a second renderer, camera and scene; the twin now owns all three. 0 black or empty in 300 loads (Chrome, Edge, Firefox and WebKit builds; dev and production) |
| **Firefox and Safari unchecked on the chosen renderer** (P01a): only Chrome and Edge were run | P01b pass checks | They take the WebGL2 fallback, which is proved in Chrome | open, reduced (P01b): Playwright's Firefox 153 and WebKit 26.5 builds both take the WebGL2 fallback and pass every shell check. A real Safari on a Mac or iPhone, and a real Android phone, are still unchecked |
| **Custom shading written for WebGL cannot be reused** (P01a): `onBeforeCompile`, `ShaderMaterial` and the `postprocessing` packages do not work on `WebGPURenderer`, and most examples online still use them | Each phase that writes a material | Write it in TSL from the node examples in `node_modules/three/examples/jsm/tsl/` | open |
| **React Three Fiber configures the canvas more than once when the renderer starts asynchronously** (P01b): anything it creates in that step can be made twice and swapped. Renderer, camera and scene are covered; its event layer is still created twice (harmless while v2 does not use R3F pointer events) | `scripts/twin/check-shell.mjs` fails a load with no terrain drawn, nothing under the cursor, or a second renderer or camera rig | Stop using `<Canvas>` and drive `createRoot` from `@react-three/fiber` directly, configuring once | open, mitigated |
| **After a rebuild the old canvas's components live on for about half a second** (P01b): React Three Fiber unmounts its tree on a timer, so old and new loop callbacks overlap | Lost-device check in `check-shell.mjs` | Shared engine state is released only by its owner (ground function, camera rig, debug hook); any new module-level state must follow the same rule | open, mitigated |
| **Touch and pinch are checked only by emulation** (P01b): a tap cancels a fly-to in the checks; pinch zoom and two-finger pan on a real phone were not tried | P13b (phone) | camera-controls' standard touch handling is in use unchanged | open |
| **The bench passes with a great deal of room because nothing costly is drawn yet** (P01c): 320 fps at the overview with 411 thousand triangles is an unlit-quality scene with no shadows, no post effects, no people. The budget lines are untested in any real sense | P02c, on the vertical slice | Budgets are rewritten there from measurement | open |
| **The tier probe is calibrated on one machine** (P01c): only the Iris Xe laptop's scores are known (3.5 on WebGPU, 1.0 on the fallback). The lines for Low, High and Ultra are multiples of that and may put other machines on the wrong tier. It measures shading speed only, not triangle throughput. Playwright's headless Firefox and WebKit (software rendering) score 0.17 and 0.02 and get Low | P02c: run the probe on at least one faster and one slower machine and a real phone | The user can pick a tier by hand; dynamic resolution covers a tier chosen too high | open |
| **Copies of a placed asset outside the camera's view are not drawn at all** (P01c): correct for the picture, wrong for shadows, since a drum just off screen should still cast one into view | P03b, when shadows arrive | Test shadow casters against the shadow cascade's volume, not the camera's | open |
| **Two copies of `sharp` in one Node process break texture compression** (P01c): seen when the root had 0.34 and a gltf-transform dependency had 0.35; the error says nothing useful ("colourspace: parameter space not set") | `npm ls sharp` after any install that touches Next or gltf-transform | Pin the root dev dependency to the version `ndarray-pixels` asks for | open, mitigated (root pinned to 0.35.5) |
| **LODs made by decimation are stand-ins** (P01c): `make_lods` cannot go below a floor set by separate shells and does not protect silhouettes or UV seams. The five test props are not review-quality assets | P02a: the first real assets get hand-made or carefully reduced LODs and the Blender review | Remove the test props and their zone once real zones exist | open |
| **`compileAsync` is used on a draw that is not yet in the scene** (P01c): it compiles against the scene's current lights. When P03b adds lights or shadows that change the light set, a pipeline compiled before the change is compiled again on first draw, which is the stall this was meant to avoid | P03b: watch the longest frame while a zone streams in after lighting changes | Compile again when the light set changes, or add draws hidden and compile in place | open |
| **Plan files are being edited by another session while a build session runs** (P01c): `STATE.md`, `README.md` and a phase file changed on disk during this session | `git status` before the closing commit; stage only this session's hunks | Re-read `STATE.md` before writing to it | open |
